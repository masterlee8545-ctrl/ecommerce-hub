# ADR-012 — 국내 농가/공장 공급처는 `vendors` 별도 테이블 + `products.supply_type` 으로 분기

**상태**: Proposed
**날짜**: 2026-05-13
**관련**: docs/SPEC.md §4, docs/DATA_MODEL.md, CPS.md, CLAUDE.md (P-4, P-5, P-9)

---

## 배경

BUYWISE 이커머스허브는 6단계 파이프라인(`research → sourcing → importing → listing → active → branding`) 위에서 동작한다. 지금까지 `sourcing` 단계의 공급자는 `suppliers` 테이블 하나(중국 1688 도매상 위주)로 통일되어 있었다.

이번에 추가하는 기능은 **국내 농가/공장으로부터 위탁판매 받을 공급처를 찾고 통화하고 거래를 확정**하는 워크플로다. 두 종류의 공급처는 본질이 다르다:

| 구분 | `suppliers` (기존) | 신규 국내 공급처 |
|---|---|---|
| 출처 | 중국 1688 / 알리바바 | 국내 사이소·김제몰 등 |
| 식별자 | 1688 셀러 ID, 영문명 | 한국 사업자번호, 한글 업체명, 대표자 |
| 협상 채널 | 채팅·메신저·견적서 | 전화 + 카톡 + 직접 방문 |
| 신뢰도 기준 | 평점, 거래량, 알리바바 인증 | 사업자등록 확인, 통화 결과, 지역 인지도 |
| 결제 통화 | CNY | KRW |
| 리드타임 | 2~6주 (운송 + 통관) | 즉시~3일 (위탁 발송) |

같은 테이블에 두 종류를 섞으면 다음 문제가 발생한다:

1. **컬럼 의미 충돌**: 사업자번호 vs 1688 셀러 ID, KRW vs CNY 등 NULL 처리 폭발
2. **신뢰도 마킹(P-3) 혼선**: 두 출처의 confidence 기준이 달라 `*_confidence` 컬럼이 모호해짐
3. **멀티테넌트 격리(P-5) 어려움**: 1688 셀러는 광역 공유, 국내 농가는 회사 격리 + 승인제 (ADR-013 참조)
4. **검색/매칭 알고리즘 분기**: 국내 농가는 품목 키워드 매칭, 1688은 영문 SKU 매칭 — 같은 SQL 쿼리로 못 풀음

또한 **상품 단위 분기**가 필요하다. 같은 사업자(예: 유어밸류)가 농산물도 팔고 공산품도 팔 수 있다. 회사 단위(`business_type`)로 분기하면 SaaS 가입자가 두 종류를 동시 운영할 수 없다 (CPS의 상용화 비전 위반).

## 결정

### D-1. 국내 공급처는 `vendors` 별도 테이블로 분리

- `suppliers` 테이블은 **중국 1688/해외 도매 전용**으로 유지
- 국내 농가/공장은 **`vendors` 신규 테이블**에 저장
- 두 테이블은 컬럼 구조도 다르고 RLS 정책도 다름 (ADR-013 참조)
- 상품-공급처 연결도 분리:
  - `products.primary_supplier_id` → `suppliers.id` (기존, 중국)
  - `products.primary_vendor_id` → `vendors.id` (신규, 국내)

### D-2. 상품마다 공급망 유형은 `products.supply_type` 으로 결정

- `products` 테이블에 신규 컬럼 `supply_type text`
- 가능한 값:
  - `'domestic_vendor'` — 국내 농가/공장만
  - `'overseas_supplier'` — 중국 도매상만
  - `'both'` — 둘 다 (희귀, 멀티 소싱)
  - `NULL` — 아직 미정 (사용자가 결정 전)
- UI 탭 노출 규칙:
  | `supply_type` | 공급처 찾기 (농가) 탭 | 도매상 찾기 (중국) 탭 |
  |---|---|---|
  | `domestic_vendor` | ✅ | ❌ |
  | `overseas_supplier` | ❌ | ✅ |
  | `both` / `NULL` | ✅ | ✅ |

### D-3. 회사 종류(`business_type`)로 분기 금지

- `companies.business_type`(`'industrial' | 'agricultural' | 'other'`)은 라벨/통계용에만 사용
- 공급처 찾기 탭 노출 결정에 사용 금지
- 이유: 모든 가입자(SaaS 비전)가 두 종류를 동시 운영 가능해야 함

### D-4. 6단계 파이프라인은 그대로 재사용

- 국내 농가 워크플로도 기존 6단계 안에서 동작
- 농가 통화/계약 단계 = **`sourcing` 단계 안의 워크플로** (새 단계 신설 X)
- 단계별 의미 매핑:
  | 공산품 단계 | 국내 농가 의미 |
  |---|---|
  | `research` | 시즌 펄스에서 키워드 발굴 |
  | `sourcing` | 농가 통화 + 후보 확정 ← 본 ADR 핵심 |
  | `importing` | 견본 수령 + 위탁 계약 체결 |
  | `listing` | 쿠팡·네이버 등록 |
  | `active` | 판매중 |
  | `branding` | 자체 브랜드화 |

### D-5. 시즌 펄스 연계

- `/research/season-pulse` 의 "🛒 담기" 클릭 시 `products` 행 생성과 함께 다음 컬럼 자동 채움:
  - `season_peak_month` (피크월)
  - `season_prep_month` (준비월)
  - `seasonality_ratio` (시즌성 배수)
  - `season_score` (5/4/2/1 스코어)
- `supply_type` 은 키워드 텍스트로 자동 추론:
  - 농산물 키워드 사전(`C:\개발\크롤링\aggregate_and_classify.py` 의 `PRODUCT_KEYWORDS`) 매칭 → `'domestic_vendor'`
  - 그 외 → `'overseas_supplier'`
  - 자신 없으면 → `NULL` (사용자가 상품 페이지에서 선택)
- 상품 상세 페이지의 "공급처 찾기" 탭에서 시즌 메타를 농가 매칭/정렬에 활용 가능 (예: "현재 피크인 농가 우선")

## 이유

### 분리가 합치보다 나은 이유 (P-4 / P-5 준수)

1. **컬럼 의미 명확화** — `vendors.bizNo` 는 한국 사업자번호 전용. `suppliers.alibaba_seller_id` 는 1688 전용. NULL 폭발 없음.
2. **RLS 정책 분리** — `vendors` 는 회사 격리 + 공유 승인 (ADR-013). `suppliers` 는 광역 공유 가능 (변경 없음).
3. **신뢰도 기준 분리** — 농가는 통화 후 ✅ confirmed. 1688은 거래 후 ✅ confirmed. 기준이 달라도 충돌 없음.
4. **검색 알고리즘 분리** — 농가 자동 매칭은 한글 품목 키워드 + 지역 + 인증. 1688은 영문 SKU + 가격대. 같은 인덱스에 끼지 않음.

### 상품 단위 분기가 회사 단위보다 나은 이유

1. **상용화 호환** — SaaS 가입자가 두 카테고리 동시 운영 가능 (강의생 확장 비전, CPS Phase 3)
2. **현실 일치** — 형은 유어밸류(농산물)에서 공산품도, 바이와이즈(공산품)에서 농산물도 다룸
3. **확장성** — 향후 일본/동남아 공급처 추가 시 `supply_type` 값만 추가하면 됨

### 6단계 재사용이 새 단계 신설보다 나은 이유

1. **모델 안정성** — 21개 테이블 + 38 페이지 사양이 6단계 가정 하에 작성됨. 7단계로 늘리면 변경 충격 큼.
2. **자동 작업 매트릭스 호환** — SPEC §3.2 의 작업 자동 생성이 그대로 동작
3. **UI 일관성** — 사이드바 네비, 대시보드 KPI 등 모두 6단계 기준

## 대안 검토

### 대안 A: `suppliers` 테이블에 컬럼 추가 (단일 테이블 유지)

- 컬럼: `kind text NOT NULL` ('overseas' | 'domestic_vendor'), `biz_no_kr text`, `vendor_meta jsonb` 등
- 장점: 마이그레이션 가벼움, 상품-공급처 연결 단순
- 단점:
  - NULL 폭발 (`alibaba_seller_id` vs `biz_no_kr` 절반 비어있음)
  - RLS 정책이 `kind` 분기 → 복잡 + 누락 위험 (P-5)
  - 검색 인덱스 효율 저하
  - **기각**: P-4 ADR-002 의 "도메인이 다른 데이터는 별도 테이블" 원칙 위반

### 대안 B: 회사 종류로 분기 (`companies.business_type`)

- `agricultural` 회사만 농가 탭 노출, `industrial` 회사만 도매상 탭 노출
- 장점: 구현 간단 (탭 노출 조건 1줄)
- 단점:
  - 한 회사가 두 카테고리 다루면 못 함 (현실과 안 맞음)
  - SaaS 가입자 다양성 제약 (CPS Phase 3 비전 위반)
  - **기각**: D-3 근거대로

### 대안 C: 농가 워크플로를 새 단계(`vendor_call`)로 신설

- `research → vendor_call → sourcing → importing → ...` 형태
- 장점: 농가 통화가 명시적 단계가 됨
- 단점:
  - SPEC §3 (6단계), §3.2 (자동 작업 매트릭스) 전면 재작성 필요
  - 사이드바, 대시보드, 칸반 보드 등 모든 UI 영향
  - 1단계 PR에 들어갈 범위 폭증
  - **기각**: D-4 근거대로 (6단계 안에 흡수)

## 위반 시 (이 ADR 어기면 즉시 불합격)

- ❌ `suppliers` 테이블에 농가 관련 컬럼 추가 (P-4 위반)
- ❌ 회사의 `business_type` 으로 농가 탭 숨김/노출 결정 (D-3 위반)
