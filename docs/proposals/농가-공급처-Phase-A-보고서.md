## 형이 결정해야 할 거 (3개)

### ① 큰 그림 맞나요?

**무엇을 만드는지**:
1. **시즌 펄스에서 키워드 발견** ("5월에 참외 떠오름") → 🛒 담기
2. **상품 안에 "공급처 찾기" 탭** 자동 생김 (농산물일 때만)
3. **농가 자동 매칭** 12개 카드로 나옴 — 점수순 (정확 일치 + 시즌 적합 + 활성도 등)
4. **카드의 [📞 통화] 누르면** 모바일에서 바로 자동 전화 + 끊으면 30초짜리 기록 폼
5. **"견본 받음 → 이 농가로 확정"** 누르면 상품-농가 연결 + 단계가 자동으로 `importing` 으로 넘어감

**왜 이렇게 만드는지**:
- 형이 지금 사이소·김제몰 다니면서 손으로 찾고 있는 일을 → 시즌 펄스랑 한 화면에서 끝내자
- 강의생들도 나중에 이 시스템 그대로 쓰게 (단, 형 농가 풀은 승인받아야 봄)

→ **이 큰 그림 맞으면 ✅, 다르면 어디가 다른지 알려주세요**

---

### ② 강의생 공유 정책 맞나요?

**제가 정한 규칙**:
- 형이 모은 농가 1,833명 = **형 자산**. 강의생은 기본적으로 못 봄
- 강의생이 "BUYWISE 농가 풀 보고 싶어요" 신청 → **형이 승인해야** 봄
- 승인받은 강의생도:
  - ✅ 농가 사업자명, 주소, 품목, 전화번호는 봄
  - ❌ **농가 생년월일/성별은 가려짐** (개인정보보호법)
  - ❌ **형이 그 농가랑 통화한 내용은 못 봄** (영업 비밀)
  - ❌ **형이 그 농가에 견적 얼마 제안했는지 못 봄** (영업 비밀)

**왜 이렇게**:
- 완전 공유: 형 1,800명 자산이 공짜로 풀림 ❌
- 완전 격리: 강의생이 매번 새로 모아야 함, SaaS 확장 비전 깨짐 ❌
- 승인제: 형이 통제 + 강의생 점진 확장 가능 ✅

→ **이 정책 맞으면 ✅, 다르면 어떻게 바꿀지 알려주세요**

---

### ③ 6단계로 나눠서 만드는 거 맞나요?

만들 분량이 큰데(테이블 5개 + 페이지 5개 + 자동 매칭 + 통화 기록 + 공유 승인 + 시즌 연계 + 분류 후처리), 한꺼번에 하면 검증 어려움. **6개 PR로 나눠서 1주일~10일 진행 예정**.

| 순서 | 무엇 | 예상 시간 | 끝나면 보이는 것 |
|---|---|---|---|
| **1번** | 농가 DB + 사이소/김제몰 CSV 임포트 + 검색 페이지 | 6~10시간 | `/vendors` 들어가면 1,833명 검색됨 |
| **2번** | 상품 페이지 "공급처 찾기" 탭 + 자동 매칭 | 4~6시간 | 참외 상품 만들면 안동참외농원 등 12곳 점수순 |
| **3번** | 통화 모달 + `vendor_call_logs` 기록 | 3~5시간 | 농가 카드 [📞] 누르면 자동 전화 + 30초 기록 폼 |
| **4번** | 강의생 공유 승인 시스템 | 5~7시간 | `/vendors/access` 에서 형이 승인/거절 |
| **5번** | 시즌 펄스 ↔ 상품 시즌 메타 자동 연결 | 2~3시간 | 시즌 펄스에서 담으면 상품에 "5월 추천, 피크 7월" 자동 표시 |
| **6번** | 사이소 농가 분류(1차농가/가공유통 등) 자동 채움 | 3~4시간 | 검색에서 "1차 농가만" 같은 필터 가능 |

**중요**: **1번 끝나야 나머지 시작 가능**. 1번이 인프라(테이블 + 데이터 임포트)라서.

→ **이 순서 맞으면 ✅, 다르면 알려주세요**

## 용어 정리 (안 알면 헷갈리는 단어)

| 용어 | 쉬운 말 |
|---|---|
| **vendors 테이블** | 농가 1명 = 1줄 들어가는 엑셀 시트. DB 안에 있는 거 |
| **supply_type** | 상품마다 "이거 농가에서 살 거? 1688에서 살 거?" 표시하는 라벨 |
| **RLS (Row Level Security)** | DB 단에서 "이 회사는 이 줄만 봐" 자동 차단. 형이 코드 안 짜도 강의생이 형 자산 못 봄 |
| **vendor_access_grants** | 승인제 테이블. "강의생 김OO 가 형 농가 풀 봐도 됨" 1줄 = 1승인 |
| **마이그레이션** | DB 구조 바꾸는 명령. drizzle-kit 이라는 도구가 자동 만들어줌 |
| **PR (Pull Request)** | "이 코드 추가해도 될까요?" 묶음. 기능 1개 = 1 PR. 검증 5+1 통과해야 머지 |
| **dedup** | 중복 제거. 같은 농가가 사이소·김제몰에 둘 다 입점하면 1줄로 묶기 |
| **also_listed_on** | 그 농가가 입점한 몰 목록. 활성도 점수에 씀 ("3개 몰 입점 = 활발한 농가") |
| **품목 키워드 매칭** | 농가 상품 설명에 "참외" 들어있으면 → "참외" 상품의 후보로 자동 매칭 |

## 위험 / 미리 알아둘 거

### 1. 데이터 숫자가 약간 흔들릴 수 있음

- 사이소(전북) 1,728건 + 김제몰류(경북) 239건 = **총 1,967건 예상**
- 사업자번호 정규화 후 같은 농가 묶으면 약 **1,833명** 예상 (124명 dedup)
- ±10% 변동 가능 — 1번 PR 끝나면 실측 숫자 보고드림

### 2. 자동 매칭 점수는 첫 안

- 가중치(정확 일치 50점 + 시즌 적합 20점 + 활성도 15점 + 지역 10점 등)는 제가 정한 첫 값
- 형이 써보고 "이 농가가 위에 떠야 되는데 아래 있네" 같은 피드백 받아서 조정함
- 2번 PR에서 가중치를 환경변수로 빼서 조정 쉽게 만들 예정

### 3. 사이소 토큰 1시간 만료

- 지금 한 번 가져온 1,728건 데이터는 DB에 있어서 영구. 검색·매칭 다 됨
- 추가로 사이소 셀러별 상품 정보 더 가져오려면 (productKeywordsAll, productsTop10 등) 토큰 다시 받아야 함
- **본 의뢰서 범위 밖**. 1~6번 PR 끝나고 별도 의뢰서로 진행

### 4. 농가 분류 정확도

- 6번 PR 에서 1,728건의 "1차_농가 / 가공유통" 분류를 정규식으로 자동 채움
- 기존 `aggregate_and_classify.py` 의 패턴이 사이소 데이터에도 잘 맞는지는 실측해봐야 함
- 샘플 100개 수동 검증하고 정확도 보고

## 확정 요청

이 3개에 ✅ / ❌ 만 주시면 1번 PR 시작합니다:

1. **큰 그림** (시즌 펄스 → 공급처 찾기 탭 → 자동 매칭 → 통화 → 확정) ?
2. **승인제 공유 정책** (생년월일/통화내용/견적은 마스킹) ?
3. **6개 PR 순서대로 진행** (1번부터 시작, 2~5번은 1번 끝나면 병렬 가능, 4번은 2번 끝나야) ?

다 ✅ 이면:
- 다음 메시지에 **"1번 PR 진행해"** 라고 보내주시면 됩니다
- 1번 PR 끝나면 (6~10시간 후) 1,833명 검색 화면 보여드리고 다음 PR 진행 여부 확정

다른 의견 있으면:
- 어디가 다른지만 알려주시면 됩니다 (예: "③번에서 4번 PR을 2번보다 먼저 했으면 좋겠어")
